O que é API REST e como ela conecta sistemas

Aprenda os fundamentos de API REST, HTTP, recursos, métodos, status codes, validação e contratos.

API é um contrato

Uma API define como outro software pode solicitar uma operação ou obter dados. Em uma aplicação Web, o navegador pode pedir uma lista de produtos ao servidor; o servidor responde em um formato combinado. O valor está no contrato: entrada, saída, regras e erros precisam ser previsíveis.

HTTP como base

APIs REST normalmente usam HTTP. GET costuma consultar, POST criar, PUT ou PATCH alterar e DELETE remover. Esses verbos não substituem a regra de negócio, mas tornam a intenção da requisição mais clara. Status codes como 200, 201, 400, 401, 403, 404 e 500 ajudam o cliente a interpretar o resultado.

Recursos e URLs

Em vez de criar uma URL diferente para cada ação arbitrária, REST organiza o domínio em recursos. `/clientes/123` representa um cliente; `/pedidos` representa a coleção de pedidos. A modelagem precisa ser coerente com o problema, e não apenas seguir um padrão visual de URL.

Validação e erros

Nunca trate o cliente como fonte confiável. O servidor deve validar tipos, campos obrigatórios, limites e autorização. Erros precisam ser úteis para o consumidor da API sem expor segredos, stack traces ou detalhes internos desnecessários.

Documente o contrato

Uma API profissional informa endpoints, parâmetros, exemplos, autenticação, respostas e erros. Testes de integração verificam se o contrato continua válido quando o código muda.

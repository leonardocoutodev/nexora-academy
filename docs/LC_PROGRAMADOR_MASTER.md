## O que preservamos da referência

A formação LC preserva os grandes eixos que fazem sentido no Programador Master:

- desenvolvimento web com HTML e CSS;
- WordPress;
- Java;
- lógica de programação;
- PHP;
- Python.

Esses eixos são usados como referência de cobertura curricular, não como conteúdo a ser copiado.

## Lacunas identificadas

A referência original apresenta lacunas relevantes para uma formação de programação atual:

1. lógica aparece depois de HTML, WordPress e Java;
2. JavaScript não aparece como componente central;
3. Git e GitHub não aparecem como competência obrigatória;
4. banco de dados não possui eixo explícito no Programador Master;
5. APIs e integração entre sistemas não aparecem como eixo próprio;
6. deploy, testes e observabilidade não formam uma progressão clara;
7. a sequência mistura desenvolvimento de sites por CMS com fundamentos de linguagem antes de consolidar uma base comum.

## Estrutura LC

### 1. Lógica de Programação e Algoritmos
Base de raciocínio antes da linguagem.

### 2. Ambiente, Terminal, Git e GitHub
Fluxo profissional mínimo para criar, versionar e publicar projetos.

Interfaces web semânticas, acessíveis e responsivas.

### 4. JavaScript para Web
Programação no navegador, DOM, eventos e APIs.

### 5. PHP e MySQL
Backend, persistência, CRUD, autenticação e segurança.

### 6. WordPress Profissional
CMS depois de o aluno compreender a Web e seus componentes.

### 7. Python
Programação geral, arquivos, automação e APIs.

### 8. Java
Orientação a objetos e construção estruturada de aplicações.

### 9. APIs, Integrações e Projeto Final
Integração full stack, testes, deploy e evidência de competência.

## Padrão de conteúdo

Cada aula deve:

- ter objetivo específico e verificável;
- ensinar o conceito em profundidade suficiente para uso real;
- usar exemplos contextualizados;
- conter prática quando ela acrescentar aprendizagem;
- evitar textos criados apenas para preencher um template;
- diferenciar reconhecimento conceitual de capacidade de aplicação;
- usar checagens rápidas sem transformar a aula em sequência de telas;
- conectar-se aos projetos do módulo;
- manter a experiência contínua de leitura aprovada na LC.

## Avaliações

O curso deverá ter:

- checkpoints aplicados por módulo;
- práticas guiadas e Labs adequados à tecnologia;
- Boss Fights em marcos relevantes, não necessariamente um por módulo;
- avaliação final aplicada;
- projeto final publicado e verificável.

## Carga horária

A carga da LC será calculada após o conteúdo real estar pronto.

Não usar:
- as 96h comerciais como hardcode;
- a soma de 147h da Ouro como meta obrigatória.

A estimativa deverá considerar:
- leitura/explicação;
- prática;
- Labs;
- avaliações;
- projetos.

## Política de propriedade intelectual

A Ouro é referência de escopo e cobertura.

Não copiar:
- textos integrais;
- narrações;
- questões;
- imagens;
- arquivos proprietários;
- atividades proprietárias.

O conteúdo LC deve ser autoral e pode ser enriquecido por documentação pública/oficial e materiais com licença compatível.
